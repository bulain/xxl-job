# PGSQL MyBatis Mapper 适配设计

日期：2026-07-26
目标：新建 `xxl-job-admin/src/main/resources/mybatis-mapper/pgsql/` 下 7 个 mapper XML 及配套 DDL，使 xxl-job-admin 可在 PostgreSQL 10+ 下正常运行。

## 1. 范围

- 新建：`mybatis-mapper/pgsql/` 7 个 XML（XxlJobInfoMapper、XxlJobLogMapper、XxlJobLogGlueMapper、XxlJobLogReportMapper、XxlJobGroupMapper、XxlJobUserMapper、XxlJobRegistryMapper），从 `mssql/` 版拷贝后改写
- 新建：`doc/db/tables_xxl_job.pgsql.sql`
- 不改动：Java 代码、`application.properties`（mapper 目录激活方式由用户自行处理）
- 前提：PostgreSQL 10+；postgresql 42.7.7 已在 `xxl-job-admin/pom.xml`

## 2. 方案选型

路线 A：从 mssql/ 版拷贝改写。mssql 版已清理干净（无反引号、无 MySQL 注释块、CONCAT 多参数化、NOT(...) 已修），与 PG 差异只剩分页、日期函数、upsert 三类。
否决路线 B（从 MySQL 根目录拷贝）：需重新处理反引号等坑。

关键决策：

- 分页：`LIMIT n OFFSET m` 形式（PG 全版本通用；FETCH FIRST 语法 PG 13+ 才支持，不采用）
- 主键：DDL 用 `GENERATED BY DEFAULT AS IDENTITY (START WITH 100)`，XML 保留 `useGeneratedKeys="true" keyProperty="id"`（PG 驱动对 getGeneratedKeys 支持可靠）
- upsert：PG 原生 `INSERT ... ON CONFLICT ... DO UPDATE`（9.5+）

## 3. XML 改写规则（相对 mssql/ 版的差异）

### 3.1 分页

| 位置 | mssql 版现状 | 改为 |
|---|---|---|
| Info/Group/User/Log pageList | `OFFSET #{offset} ROWS FETCH NEXT #{pagesize} ROWS ONLY` | `LIMIT #{pagesize} OFFSET #{offset}` |
| Info scheduleJobQuery、Log findClearLogIds（外层）、Log findFailJobLogIds、Log findClearLogIds 内层、LogGlue removeOld 内层 | `OFFSET 0 ROWS FETCH NEXT #{n} ROWS ONLY` | `LIMIT #{n}` |

### 3.2 XxlJobRegistryMapper

- `DATEADD(SECOND, -#{timeout}, #{nowTime})`（findDead、findAll 两处）
  → `#{nowTime} - make_interval(secs => #{timeout})`
- `registrySaveOrUpdate` 的 MERGE 改为：

```sql
INSERT INTO xxl_job_registry (registry_group, registry_key, registry_value, update_time)
VALUES (#{registryGroup}, #{registryKey}, #{registryValue}, #{updateTime})
ON CONFLICT (registry_group, registry_key, registry_value)
DO UPDATE SET update_time = #{updateTime}
```

依赖 DDL 中 `(registry_group, registry_key, registry_value)` 唯一约束。

### 3.3 保留不动

- `AS` 表别名：PG 合法
- 6 个 save 的 `useGeneratedKeys="true" keyProperty="id"`：PG 驱动可靠回填 IDENTITY
- `CONCAT('%', #{x}, '%')`：PG 原生 variadic CONCAT
- `NOT (...)`、无反引号、语句无结尾分号、`<![CDATA[ <= ]]>`

## 4. DDL 脚本 `doc/db/tables_xxl_job.pgsql.sql`

- 头部注释说明执行方式：先 `CREATE DATABASE xxl_job;`，再连到该库执行剩余部分（`\connect` 为 psql 元命令，不写入脚本正文）
- 8 张表（xxl_job_info、xxl_job_log、xxl_job_log_report、xxl_job_logglue、xxl_job_registry、xxl_job_group、xxl_job_user、xxl_job_lock），对齐 MySQL 结构：
  - 主键：`id INT GENERATED BY DEFAULT AS IDENTITY (START WITH 100) PRIMARY KEY`（`xxl_job_log.id` 为 `BIGINT`）；`BY DEFAULT` 允许种子显式 id=1，`START WITH 100` 避开冲突
  - 类型映射：`datetime` → `TIMESTAMP`；`int(11)` → `INT`；`bigint(20/13)` → `BIGINT`；`tinyint(4)` → `SMALLINT`（PG 无 tinyint）；`varchar(n)` → `VARCHAR(n)`（PG 原生 UTF-8，无需 NVARCHAR/N 前缀）；`text`/`mediumtext`（glue_source、trigger_msg、handle_msg、address_list）→ `TEXT`
- 索引/唯一约束：
  - `xxl_job_log_report(trigger_day)` UNIQUE
  - `xxl_job_registry(registry_group, registry_key, registry_value)` UNIQUE
  - `xxl_job_user(username)` UNIQUE
  - `xxl_job_lock(lock_name)` PRIMARY KEY
  - `xxl_job_log` 4 个普通索引：trigger_time、handle_code、(job_id, job_group)、job_id
- 种子数据与 MySQL 版一致：示例执行器组（id=1）、测试任务1（id=1）、admin 用户（id=1，密码 md5）、`schedule_lock`；日期用 `'2018-11-03 22:21:31'` 字面量；字符串无需 `N''` 前缀

## 5. 验证

- 改后对所有 XML 做良构性校验
- 本机无 PostgreSQL 实例：SQL 按 PG 10+ 语法人工复核，不做实际执行
- 风险点：ON CONFLICT 依赖 registry 三列唯一约束；`make_interval(secs => ...)` 参数须为 double/integer 兼容类型（timeout 为 int，合法）
